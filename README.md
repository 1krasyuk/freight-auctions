# Freight Auctions — грузовые аукционы

SPA для поиска грузовых аукционов, просмотра подробной информации и работы со ставками. Проект реализован по готовой OpenAPI-схеме; локальный backend эмулируется stateful MSW-моками.

## Возможности

- список аукционов с пагинацией и сортировкой;
- быстрые и расширенные фильтры с синхронизацией в URL;
- поиск по номеру заявки;
- skeleton, empty и error states;
- адаптивные карточки для desktop и mobile;
- intent-prefetch детальной страницы;
- детальная информация об аукционе, маршруте, грузе, организаторе, оплате и параметрах торгов;
- отдельная route-backed вкладка ставок;
- отображение рейтинга, цен с НДС и без НДС, победивших и отменённых ставок;
- установка и изменение ставки через форму с валидацией;
- обработка ограничений доступа и скрытых данных из DTO;
- светлая, тёмная и системная темы.

## Запуск

Требуется Node.js 20.19+ или 22.12+ и npm.

```bash
# Клонировать репозиторий
git clone https://github.com/1krasyuk/freight-auctions.git

# Перейти в папку проекта и установить зависимости
cd freight-auctions
npm install

# Запустить проект
npm run dev
```

После запуска приложение доступно по адресу [http://localhost:5173](http://localhost:5173).

Production-сборка:

```bash
npm run build
```

## Архитектура и владельцы состояния

Исходный код организован по Feature-Sliced Design:

```text
src/
├── app/       # провайдеры и запуск MSW
├── routes/    # тонкие файловые маршруты TanStack Router
├── pages/     # композиция страниц
├── features/  # пользовательские действия, например форма ставки
├── entities/  # аукцион, data-access и MSW-моки
└── shared/    # API transport, общие библиотеки и UI-примитивы
```

Каждый вид состояния имеет отдельного владельца:

| Состояние                                     | Владелец                      |
| --------------------------------------------- | ----------------------------- |
| Данные API и кеш                              | TanStack Query                |
| Фильтры, пагинация и открытие формы по ссылке | TanStack Router search params |
| Поля и ошибки формы ставки                    | React Hook Form + Zod         |
| Общая клиентская тема                         | Zustand                       |
| Изменяемое состояние mock-backend             | Изолированный MSW store       |

Route-файлы выполняют валидацию search params, запускают loaders и подключают страницы. Компоненты страниц не импортируют generated transport напрямую: обращения к API сосредоточены в data-access сущности аукциона.

## API, OpenAPI и MSW

Источник данных — [`openapi/openapi.auctions.v0.json`](./openapi/openapi.auctions.v0.json). Generated-файл не редактируется вручную.

Используются четыре endpoint:

| Метод  | Endpoint                              | Назначение                                   |
| ------ | ------------------------------------- | -------------------------------------------- |
| `POST` | `/api/v1/auctions/list`               | Фильтрация, сортировка и пагинация аукционов |
| `GET`  | `/api/v1/auctions/{auctionUuid}`      | Детальная информация                         |
| `GET`  | `/api/v1/auctions/{auctionUuid}/bets` | Текущие ставки и рейтинг                     |
| `POST` | `/api/v1/auctions/{auctionUuid}/bets` | Установка или изменение ставки               |

MSW handlers используют те же generated DTO. После успешной ставки mock-store обновляет:

- текущую цену в list и detail;
- торговый статус пользователя;
- состояние собственной ставки;
- список ставок и места участников.

Ошибочные запросы возвращают контрактные `ProblemDetail` или `ValidationProblem`. Для ставки проверяются `can_set_bet`, положительная конечная цена и доступные в detail DTO ограничения `min`, `max`, `step`.

## Маршруты

| URL                                       | Экран                                                   |
| ----------------------------------------- | ------------------------------------------------------- |
| `/`                                       | Список аукционов                                        |
| `/auctions/:auctionUuid`                  | Детальная информация                                    |
| `/auctions/:auctionUuid/bets`             | Ставки участников                                       |
| `/auctions/:auctionUuid/bets?setBet=true` | Ставки с открытой формой установки или изменения ставки |

Search params списка валидируются Zod-схемой. Невалидные значения получают безопасные fallback-значения и не ломают страницу.

## Ручная проверка

Для проверки проекта использовались следующие сценарии:

1. Открытие списка без search params и с некорректными значениями в URL.
2. Применение быстрых и расширенных фильтров, общий сброс и empty state.
3. Сортировка, изменение количества строк и переходы пагинации с сохранением фильтров.
4. Intent-prefetch и переход из карточки на detail.
5. Прямое открытие detail и bets URL, reload и навигация назад/вперёд.
6. Отображение открытых и скрытых контактов, адресов, цены груза и истории ставок.
7. Empty и pending states, а также 404-состояния detail и ставок при неизвестном UUID.
8. Открытие формы ставки по `?setBet=true`, закрытие с очисткой search param.
9. Клиентская валидация обязательной цены, `min`, `max` и `step`.
10. Успешная новая и повторная ставка, обновление list/detail/bets после mutation.
11. Success toast после ставки и отображение клиентских ошибок формы.
12. Переключение темы и адаптивность основных экранов на desktop/mobile.

## Автоматические тесты

Unit-тесты расположены рядом с проверяемыми модулями (`*.test.ts`) и покрывают:

- parsing и безопасные fallback search params;
- сборку контрактного request списка;
- схему валидации ставки;
- фильтрацию, сортировку и пагинацию чистой MSW-логики;
- обработку ошибок ставки без изменения mock-store;
- создание и обновление активной ставки, сохранение отменённой ставки и пересчёт рейтинга;
- форматирование, сортировку и подсчёт участников;
- route-backed search param формы ставки.

Запуск:

```bash
npm run test
```

## Решения, допущения и ограничения

- DTO списка не содержит шаг ставки. Значение не синтезируется на клиенте и используется только на detail, где оно присутствует в контракте.
- Ответ `/bets` интерпретируется как актуальный рейтинг, а не полный журнал изменения каждой цены. Повторная активная ставка обновляется, отменённая сохраняется отдельно, а следующая ставка участника создаёт новую активную запись.
- Кратность шага проверяется относительно `min`, а при отсутствии `min` — относительно нуля.
